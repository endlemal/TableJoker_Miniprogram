# 按比例重新构图的 SVG 插画

裁切只能保留一张图的一部分：横幅里的月亮，到了竖图里就会被切掉。按比例重新构图，是让每种尺寸都重新摆一遍元素：地平线高度、焦点位置、元素大小都按画面比例和短边来算。同一个场景在 3:1 和 9:16 里都完整、好看。

## 做法

本仓库的实现是 `src/common/cover-art.js`，新场景照着写：

- **几何**：`geo(W, H)` 给出宽高比 `a`、短边 `m`、`wide`（a ≥ 1.15）、`tall`（a < 0.9）和地平线高度 `hz`。横图的地平线低一些，竖图留更多天空。
- **焦点**：月亮、太阳、灯塔这类焦点，横图放在右侧三分之一，竖图居中偏上。大小按短边算，比如 `m * 0.2`。
- **随机**：用固定种子的伪随机数（`seeded(n)`），同一场景、同一尺寸每次输出完全一样，方便对比和缓存。
- **图元**：`C/E/R/P/D` 分别是圆、椭圆、矩形、多边形和路径，坐标统一保留一位小数。另有地形线 `ridge`、星空 `stars`、松树 `pine` 和 `forest` 等辅助函数。
- **尺寸**：banner 600×200、wide 640×360、share 500×400、square 480×480、portrait 450×600、story 450×800。容器比例不固定时，用 `nearestSize(比例)` 按对数距离选最接近的尺寸。
- **寓意**：每个场景配一句和玩法相关的暗喻，写在场景列表里（本仓库是 `src/mock/data.js` 的 `coverScenes`）。

## 步骤

1. 写场景函数 `(W, H) => SVG 内容`，加进场景表。
2. 生成全部尺寸，用 `python3 scripts/validate_svg.py <目录>` 校验：必须能按严格 XML 解析，数值里不能有 `NaN`、`undefined`。用作 data URI 或导入 Figma 时，图片都是按 XML 解析的，有一处错就整张不显示。
3. 用 `python3 scripts/render_sheet.py <目录> <输出.png>` 渲染成对比图（每行一个场景，每列一个尺寸），逐行检查。
4. 按检查结果调参，重复第 2、3 步，直到所有尺寸都成立。
5. 接到界面上：按容器取尺寸（本仓库是 `svg.js` 的 `coverStyle(场景, 尺寸)`）；再导出给设计（见 `design-asset-export` 技能）。

## 坑

- **前后两层三角形的树林**：后面那层颜色更浅时，树缝里会露出一排「倒三角」。解决办法是让树冠线直接衬在天空上，或者只在两侧放高树丛、中间留空。
- **焦点元素太小**：比如闪电，长度要从云底算到目标物，否则在横幅里只剩一个小符号。大面积的光晕圆很容易看起来像星球或胶囊，宁可不要。
- **竖图容易空**：天空太多时，在两侧加高大的前景元素框住画面。
- **SVG 里有 `transform="rotate(...)"` 时**：转 data URI 必须编码括号（见 `mp-style-perf-check` 技能）。
- **对比图测试**：不要用全局字符串替换去改 SVG 的宽高，会连带改掉内部元素，看起来像插画坏了。
