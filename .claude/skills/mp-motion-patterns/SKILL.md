# 小程序交互动效模式库

小程序的动画要同时照顾两件事：视图层的 CSS 动画很流畅；逻辑层每次 `setData` 都有成本。所以能用 CSS 关键帧和过渡完成的，就不要靠 JS 逐帧改样式；必须由 JS 驱动时，只改最小的那段样式。

下面每个模式都写了适用场景和要点，完整代码在 `references/patterns.md`，用到哪个就读哪一节。

## 模式

| 模式 | 适用场景 | 要点 |
|---|---|---|
| 可重复触发的关键帧 | 点一次播一次的弹跳、旋转 | 两套内容相同、名字不同的关键帧轮流切换（`pop-0` / `pop-1`），不改 DOM 就能重播 |
| 悬浮凹槽导航 | 底部导航，选中球跟随 | 两倍宽的凹槽 SVG 整体平移。模块级的 `lastIndex` 记「当前页面对应的项」，而不是点击的项，跳页后新页面从上一页的位置滑过来。跳转前不要先改 `active` |
| 卡片展开成详情 | 帖子、作品详情 | 量出卡片位置 → 替身元素从卡片位置过渡到顶图位置 → 正文从下方浮上来；关闭时重新量位置再收回。替身的位置样式和封面图要拆成两个元素 |
| grid 折叠面板 | 常见问题、说明文字 | `grid-template-rows` 从 `0fr` 过渡到 `1fr`，内层 `min-height: 0; overflow: hidden`，不用量高度。收起时保留文字，避免动画结束前闪空。可以嵌套 |
| 入场错落 | 瀑布流、卡片列表 | 相交监听给进入视口的卡片加类名，延迟按列内序号递增并设上限。H5 下用一次性错落兜底 |
| 数字递增 | 数据指标 | 进入视口时触发。逻辑层没有 `requestAnimationFrame`，用 `setTimeout` 每 32ms 走一步，缓出曲线，总时长约 900ms |
| 滚到底切换按钮 | 长页面的主操作 | 页面末尾放一条标记线；看到它时导航栏下沉淡出（`hidden` 属性），底部按钮延迟 0.12s 浮现；往回滑时反向 |
| 吸顶分类与滑块 | 筛选标签 | 标签等宽，选中块按序号 `translateX`，用弹性曲线；切换时列表先淡出，再重新入场 |
| 横滑卡片缩放 | 推荐卡片 | swiper 的当前项 `scale(1)`，其余 `scale(.92)` 并降低透明度 |
| 徽章弹出 | 认证标识、点赞 | `cubic-bezier(.34, 1.56, .64, 1)` 回弹；延迟 0.4s 左右再出现，让人看到「加上去」的过程 |
| 多元素同步循环 | 一段动画里多个元素配合（发牌、光束、光环） | 所有元素用同一个时长，各自在关键帧的不同百分比上动作；同时开始，天然同步 |
| 下拉关闭 | 全屏详情 | 内容在顶部时跟手下移并轻微缩小，超过阈值就关闭；低端机建议用 WXS 在视图层处理 |

## 每次都要做

- **减少动态效果**：在 `@media (prefers-reduced-motion: reduce)` 里关掉动画和过渡，并直接显示最终状态（比如牌已经落在桌上、徽章已经显示）。
- **验证**：用 `uniapp-h5-regression` 技能把动画放慢录成 GIF，抽帧检查。小程序独有的部分（WXS、原生组件）交给用户在开发者工具里确认。
- **性能**：动画只改 `transform` 和 `opacity`。大段的 data URI 样式不要和会变的样式写在同一个元素上（见 `mp-style-perf-check` 技能）。
